# PROJECT_SPECIFICATION

Обновлено: 2026-09-16

## Статус

`Excel таблицы в сделке и экспорт данных из CRM v.47` - релизная browser-only версия приложения для Bitrix24 Marketplace.

## Назначение

Приложение добавляет в карточку CRM-сделки вкладку `Excel таблицы в CRM`, где пользователь ведет расчеты по сделке в Excel-подобной таблице, подтягивает значения CRM-полей, форматирует ячейки, работает с несколькими листами и экспортирует заполненную область в Excel-compatible `.xls`.

Приложение не использует backend, серверные секреты, внешнюю базу данных и `.env`.

## Runtime

Рабочий runtime состоит из файлов:

- `install.html`
- `install.js`
- `install.css`
- `index.html`
- `app.js`
- `style.css`

`install.js` делает установку идемпотентной: снимает старую привязку `CRM_DEAL_DETAIL_TAB` через `placement.unbind`, затем регистрирует вкладку через `placement.bind`.

`index.html`, `style.css` и `app.js` работают внутри iframe Bitrix24. Все обращения к Bitrix24 идут через `BX24.callMethod`.

## UI

- Верхняя зона содержит название приложения и кнопки `Экспорт в Excel` / `Обновить поля`.
- Основная зона - таблица.
- Нижняя зона содержит группы листов, статус текущего листа вида `Сделка, Лист 1: 9 строк, 7 столбцов` или `Общие, Лист 1: 9 строк, 7 столбцов`, а также номер версии `v.47`.
- Верхняя зона содержит кнопку `Помощь`, которая открывает встроенное окно с инструкцией и чатом поддержки.
- Индикатор количества полей сделки в нижней панели отсутствует.
- Версия отображается мелким текстом в правой нижней части приложения.
- Таблица остается горизонтально и вертикально прокручиваемой внутри своей области.

## Листы

Есть две группы листов:

- `Листы сделки` - индивидуальные листы конкретной сделки.
- `Общие листы` - листы воронки, общие для сделок одной воронки.

Правила:

- в каждой группе доступно до 7 листов;
- первый лист каждой группы использует старый базовый ключ хранения для обратной совместимости;
- дополнительные листы получают суффиксы `-sheet-2`, `-sheet-3` и далее;
- список листов группы хранится с суффиксом `-sheet-list-v1`;
- пустые дополнительные листы удаляются при закрытии вкладки/карточки и после синхронизации;
- после автоочистки листы перенумеровываются без пропусков.

## Хранение

Основное хранилище - Bitrix24 entity storage:

```text
exctabb24
```

`localStorage` используется как кеш и fallback для локального режима.

Ключи:

```text
excel-tab-b24-grid-deal-v1-{dealId}
excel-tab-b24-grid-funnel-v1-{categoryId}
excel-tab-b24-grid-pending-deal-v1
```

`excel-tab-b24-grid-pending-deal-v1` используется только до определения ID сделки. Это исключает подхват старого общего локального листа при открытии новой сделки.

ID сделки определяется с приоритетом:

1. Текущий URL карточки / referrer.
2. Прямые placement/query значения.
3. Вложенные placement options.

Такой порядок защищает от устаревших placement-параметров Bitrix24.

## Таблица

- Стартовый размер: 9 строк и 7 столбцов.
- Минимальная область после сжатия: 9x7.
- Максимальный размер листа: 3000 строк и 3000 столбцов.
- Пустые крайние строки и столбцы не блокируют дальнейшее добавление.
- Кнопки `+` у таблицы добавляют строку или столбец.
- Через ПКМ по заголовку строки доступны команды `Добавить строку`, `Добавить 4 строки`, `Удалить строку`.
- Через ПКМ по заголовку столбца доступны команды `Добавить столбец`, `Добавить 4 столбца`, `Удалить столбец`.
- Одну строку можно перетащить за номер строки.
- Один столбец можно перетащить за буквенный заголовок.
- После переноса строки/столбца нумерация и буквенная разметка пересчитываются автоматически.

При вставке, удалении и переносе строк/столбцов вместе с данными переносятся:

- значения;
- форматирование;
- перенос текста;
- высоты строк;
- ширины столбцов;
- CRM-привязки;
- формулы и ссылки.

## Выделение

- Поддерживается выбор одной ячейки, диапазона, строк, столбцов и всей таблицы.
- Диапазон всегда получает синюю внешнюю границу.
- Если выбранная ячейка имеет заливку, синяя граница остается видимой поверх заливки.
- Граница выделения рисуется overlay-слоем поверх содержимого ячейки.

## CRM-поля

Поля сделки загружаются через `crm.deal.fields`, текущие значения сделки - через `crm.deal.get`.

Пользователь может выбрать поле CRM из поповера активной ячейки. В ячейку вставляется человекочитаемое значение, а в состоянии листа сохраняется привязка `cellKey -> fieldId`.

При загрузке и по кнопке `Обновить поля` привязанные ячейки обновляются текущими значениями сделки.

Для старых листов, где значения CRM-полей сохранились, а `fieldBindings` были потеряны, v46 восстанавливает привязку только при однозначном совпадении значения ячейки с текущим значением одного поля сделки. Если одинаковое значение встречается у нескольких полей, привязка не восстанавливается автоматически.

Форматы CRM-значений:

- `date`: `16.09.2026`
- `datetime`: `03:00 (+3ч) 16.09.2026г.`
- пользователь, контакт, компания и стадия выводятся как человекочитаемые значения, если соответствующие данные доступны через REST.

## Формулы

Формула начинается с `=`.

Поддерживаются:

- ссылки на ячейки `A1`, `B2`, `AA10`;
- числа;
- скобки;
- `+`, `-`, `*`, `/`, `%`, `^`.

Приоритет операций соответствует Excel-подобной модели. Оператор `^` имеет приоритет выше умножения и деления.

В режиме редактирования показывается исходная формула. В обычном режиме показывается рассчитанное значение. Ошибки вычисления отображаются как `#ОШИБКА`, ссылки на удаленные ячейки - как `#REF!`.

Последние формулы хранятся в `excel-tab-b24-recent-formulas-v1`, сохраненные формулы - в `excel-tab-b24-saved-formulas-v1`.

## Форматирование

Поддерживается:

- перенос текста;
- заливка;
- жирный;
- курсив;
- кегль 11/13/15/18 pt;
- горизонтальное выравнивание;
- вертикальное выравнивание;
- ручная ширина столбцов;
- ручная высота строк;
- автоподгонка ширины/высоты.

Для ячеек с переносом текста область ввода подстраивается под размер ячейки, чтобы не было двойной визуальной обводки.

## Буфер и история

- Копирование диапазона работает через `Ctrl+C` и кнопку `Копировать`.
- Вставка работает через `Ctrl+V` и кнопку `Вставить`.
- Буфер переносит значения, форматирование, перенос текста и CRM-привязки.
- Формулы при вставке пересчитывают относительные ссылки.
- Undo/redo хранит историю состояния текущего листа.
- Лимит истории: 15 снимков.

## Экспорт

Экспорт создает Excel-compatible HTML `.xls`.

В экспорт попадает только заполненная область. Пустой лист экспортируется как одна пустая ячейка.

Сохраняются:

- формулы;
- числовые значения;
- текстовые значения;
- ширины столбцов;
- высоты строк;
- границы;
- заливка;
- жирный, курсив, кегль и выравнивание.

Имя файла:

```text
Excel таблицы в сделке и экспорт данных из CRM deal {dealId}.xls
```

В локальном режиме без `dealId` суффикс сделки не добавляется.

## Релиз v47

v47 добавляет пользовательскую помощь внутри приложения:

- кнопка `Помощь` в верхней панели приложения;
- встроенное окно с простой инструкцией по использованию;
- виджет открытой линии для обращения в поддержку.

## Релиз v46

v46 фиксирует финальное рабочее состояние:

- убран индикатор количества полей сделки;
- исправлено открытие новых сделок с пустым deal-листом;
- добавлен отдельный pending-ключ до определения сделки;
- ID из текущей карточки имеет приоритет над устаревшими placement-параметрами;
- восстановление потерянных CRM-привязок старых листов остается внутренней логикой, без отдельного индикатора в интерфейсе;
- тестами покрыты ключи хранения, приоритет ID, восстановление привязок, формулы, вставка, удаление и перенос строк/столбцов.
